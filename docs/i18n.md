# Internationalisation

## Locales

23 languages, one JSON file each, in `packages/shared/src/locales/`:

`en` `fr` `de` `es` `it` `pt` `nl` `pl` `cs` `ru` `uk` `tr` `ar` `ja` `ko` `zh` `da` `nb` `sv` `fi` `hu` `ro` `el`

`en.json` is the source of truth: a key exists if and only if it exists in `en.json`.

## Rules

1. **No hardcoded user-facing string.** Labels, placeholders, tooltips, dialog text, button text, error messages and notifications all use `t('section.key')` from `react-i18next`.
2. **Every key in all 23 files.** Adding, renaming or removing a key means editing all 23.
3. **Real translations.** Each file holds the text in its own language — never the English string as a placeholder. Keep product and protocol names (Seedora, Transmission, DHT, PEX, µTP) untranslated.
4. **Preserve interpolation.** `{{variable}}` placeholders must appear, unchanged, in every translation.
5. **Do not select DOM elements by translated text** (placeholder, label). Use a `ref` or a `data-*` attribute.

## Keys

- Dot-separated, namespaced by feature: `toolbar.addTorrent`, `statusBar.freeOfTotal`, `dialog.confirmDelete`.
- Top-level sections in use: `app`, `toolbar`, `statusBar`, `sessionStats`, `filter`, `status`, `torrent`, `priority`, `details`, `peersTab`, `trackersTab`, `optionsTab`, `filesTab`, `contextMenu`, `columnMenu`, `dialog`, `server`, `settings`, `speedTab`, `networkTab`, `downloadTab`, `queueTab`, `prefs`, `notification`, `errorBoundary`, `format`, `errors`, `native`. Put a key in the section of the component that owns it; add a section only for a new feature area.
- Match the existing key order inside a section (most sections are not alphabetical today), and use the same order across files.
- Interpolation: `"deleteConfirm": "Delete {{count}} torrents?"` → `t('dialog.deleteConfirm', { count })`.

## One registry, three consumers

The locale files are registered once, in `packages/shared/src/locales/index.ts` (23 static imports and the `localeResources` map for i18next). Static imports work in both Vite and Next.js, so no host needs its own loader.

| Consumer | File | How it uses the registry |
|---|---|---|
| Electron renderer and web | `packages/shared/src/lib/i18n.ts` | initialises i18next with `localeResources`; `apps/web/src/lib/i18n.ts` re-exports it |
| Electron main process | `src/main/i18n/main-i18n.ts` | `import.meta.glob` over the locale files, keeping only the `native` section; `t('native.…')` for the menu, tray and native dialogs |

The renderer and web detect the language from `navigator.language` and fall back to `en`. Main follows the stored `language` preference (`setLanguage`, called at startup and when preferences change) and falls back to English, then to the key.

**Adding a language** touches three places:

1. `packages/shared/src/locales/<code>.json` — complete, translated, including the `native` section.
2. `packages/shared/src/locales/index.ts` — the import and the `localeResources` entry.
3. `packages/shared/src/lib/i18n-utils.ts` — the native name in `LANGUAGE_NAMES` (drives the language picker).

`packages/shared/src/lib/i18n.test.ts` fails when the files, the registry and `LANGUAGE_NAMES` drift apart. The main process needs no change: it discovers the files itself.

## Main-process strings (`native.*`)

The `native` section of each locale file holds what the main process shows: `native.menu.*`, `native.tray.*` (with `_one` / `_other` plural forms), `native.scriptGuard.*`, `native.exportSecrets.*` and `native.configError.*`. Edit it like any other section, in all 23 files. `{{appName}}` and similar placeholders are filled by `t()` in `src/main/i18n/main-i18n.ts`.

## Gate

```bash
npm run i18n:check
```

(`scripts/i18n-check.mjs`) compares every locale against `en.json` and fails on missing keys, extra keys, `{{placeholder}}` mismatches and incomplete plural families (every category `Intl.PluralRules` lists for the language, e.g. `_one/_few/_many/_other` in ru, uk, pl, cs and all six forms in ar; `many` is not required in fr, es, it, pt where it only covers millions). Run it after any locale edit; CI runs it on every pull request.

## Current state

- `npm run i18n:check` passes: 23 locales in sync with `en.json` (491 keys, measured 2026-11-15).
- `npm run i18n:check -- --untranslated` lists values identical to English (informational). Some are legitimate (product and protocol names); others may still need review.
- Remaining hardcoded strings: check `packages/shared/src/lib/format.ts` and `apps/web/src/lib/server-actions/` before assuming they are covered; the backlog (`bd list`) tracks the known ones.
